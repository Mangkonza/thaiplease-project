# ThaiPlease

ระบบชำระเงินร้านค้าชุมชนแบบโครงการรัฐช่วยจ่าย (อิงรูปแบบไทยช่วยไทยพลัส) พร้อม AI Shop Performance Advisor สำหรับร้านค้า
โปรเจกต์วิชา Web Application เป็นระบบจำลอง ไม่มีการเรียกเก็บเงินจริง

## รันทั้งระบบด้วยคำสั่งเดียว

ต้องมี Docker Desktop

```powershell
docker compose up -d --build
```

ครั้งแรกจะสร้างฐานข้อมูล ตาราง และข้อมูล demo ให้เอง

ระบบมี 3 container:

| Container | หน้าที่ | URL |
|---|---|---|
| `thaiplease_app` | frontend และ backend อยู่ด้วยกัน backend เสิร์ฟทั้งหน้าเว็บและ API รูปที่อัปโหลดเก็บใน volume `uploads_data` | หน้าเว็บ http://localhost:8080 และ API http://localhost:8080/api/v1 |
| `thaiplease_postgres` | ฐานข้อมูล แยกไว้ต่างหากเพื่อให้ข้อมูลอยู่ใน volume ของตัวเอง | `localhost:5433` |
| `thaiplease_pgadmin` | หน้าเว็บสำหรับดูฐานข้อมูล | http://localhost:5050 |

`Dockerfile` ที่ root ของ repo build ในสองขั้น ขั้นแรก build หน้าเว็บ React เป็นไฟล์ static ขั้นที่สองนำไฟล์นั้นไปไว้ใน image ของ backend แล้วตั้ง `FRONTEND_DIST` ให้ backend เสิร์ฟไฟล์เหล่านั้น

บัญชีทดสอบใช้รหัสผ่าน `Test1234!` ทุกบัญชี:

- `admin@thaiplease.test`: ผู้ดูแลระบบ
- `merchant.a@thaiplease.test` (ร้านกาแฟบ้านสวน) และ `merchant.b@thaiplease.test` (ข้าวมันไก่ป้าแดง): เจ้าของร้าน
- `merchant.c@thaiplease.test` ถึง `merchant.j@thaiplease.test`: เจ้าของร้านอีก 8 ร้าน (รวมร้านเปิดใช้งาน 10 ร้าน)
- `citizen01@thaiplease.test` ถึง `citizen80@thaiplease.test`: ประชาชน

รายละเอียดข้อมูล demo อยู่ใน [backend/seed/README.md](backend/seed/README.md)

ถ้าต้องการล้างข้อมูลแล้วเริ่มใหม่ ให้รันคำสั่งด้านล่าง คำสั่งนี้จะลบข้อมูลในฐานข้อมูลทั้งหมด:

```powershell
docker compose down -v
docker compose up -d --build
```

ถ้าต้องการใช้รายงาน AI ให้ใส่ `AI_API_KEY` ใน `backend/.env` (คัดลอกจาก `backend/.env.example`) แล้วรัน `docker compose up -d` ใหม่ ถ้าไม่ใส่ ระบบส่วนอื่นยังใช้งานได้ปกติ
`JWT_SECRET` ใน compose มีค่าเริ่มต้นสำหรับใช้ในเครื่องเท่านั้น ถ้าจะเปิดให้คนอื่นเข้าใช้ ให้ตั้งค่าใหม่ใน shell หรือในไฟล์ `.env` ข้าง `docker-compose.yml`

## รันแบบพัฒนา (แก้โค้ดแล้วเห็นผลทันที)

```powershell
docker compose up -d postgres
```

เปิด terminal สองหน้าต่าง หน้าต่างแรกรัน backend (ครั้งแรกให้คัดลอก `.env.example` เป็น `.env` ก่อน):

```powershell
cd backend
npm install
npm run dev
```

หน้าต่างที่สองรัน frontend:

```powershell
cd frontend
npm install
npm run dev
```

Backend อยู่ที่ port 5000 และ frontend อยู่ที่ http://localhost:5173 ทั้งสองส่วนใช้ฐานข้อมูลเดียวกับ container `thaiplease_app` และรันพร้อมกันได้ เพราะใช้คนละ port

## ระบบทำอะไรได้บ้าง

**ประชาชน**
- ต้องเข้าสู่ระบบก่อนใช้งานทุกหน้า ร้านค้าและผู้ดูแลระบบเข้าระบบแล้วไปหน้าจัดการของตัวเองทันที
- จ่ายเงินแบบแอปเป๋าตัง: สแกน QR รับเงินของร้าน (กล้อง หรืออัปโหลดรูป QR หรือกดจำลองการสแกนสำหรับ demo) → ระบุยอด → ใส่ PIN 6 หลัก → ได้สลิป ซึ่งเปิดดูซ้ำได้จากประวัติ
- กระเป๋าเงินจำลอง: เติมเงินได้ครั้งละไม่เกิน 10,000 บาท (ไม่ผูกธนาคารจริง) ตอนจ่ายหักเฉพาะส่วนที่ประชาชนจ่าย ถ้าคืนเงินจะคืนเข้ากระเป๋า ประชาชนใน demo มียอดเริ่มต้นคนละ 1,000 บาท
- PIN เก็บแบบ bcrypt hash ใส่ผิด 5 ครั้งล็อก 15 นาที ตั้ง PIN ครั้งแรกตอนจ่ายเงินหรือที่หน้ากระเป๋าเงิน
- ค้นหาร้านและจ่ายเงิน ระบบคิดยอดตามลำดับ: ยอดเต็ม → ส่วนลดแคมเปญร้าน → คูปอง → รัฐช่วยจ่าย 60% ของยอดที่เหลือ → ประชาชนจ่ายส่วนที่เหลือ
- รัฐช่วยจ่ายมีเพดาน 200 บาท/วัน, 2,000 บาท/เดือน และ 8,000 บาทตลอดโครงการ คูปองไม่นับรวมในเพดานนี้
- ได้ 1 เหรียญทุก 25 บาท ใช้ 100 เหรียญแลกคูปองลด 20 บาท คูปองใช้ได้เมื่อซื้อขั้นต่ำ 100 บาท มีอายุ 30 วัน และใช้ได้ 1 ใบต่อรายการ
- ขอคืนเงินได้ภายใน 7 วันหลังจ่าย ร้องเรียนร้านได้ และดูสถานะคำขอได้
- รับภารกิจ เช่น ลองร้านใหม่ 2 ร้านภายใน 30 วัน รับ 50 เหรียญ

**ร้านค้า**
- หน้า "QR รับเงิน" แสดงและดาวน์โหลด QR ของร้าน และอัปโหลดรูปหน้าร้าน (JPG, PNG, WEBP ไม่เกิน 2 MB) รูปแสดงในหน้าค้นหาร้าน หน้าร้าน และหน้าจ่ายเงิน
- Dashboard ยอดขาย และรายงาน AI ที่วิเคราะห์ปัญหาพร้อมเสนอโปรโมชัน
- สร้างแคมเปญจากข้อเสนอของ AI แล้ววัดผลแบบแบ่งกลุ่มทดลองกับกลุ่มควบคุม
- อนุมัติหรือปฏิเสธคำขอคืนเงินภายใน 3 วัน
- ดูยอดรอรับจากโครงการ คือส่วนที่รัฐช่วยจ่ายและคูปอง ซึ่งโครงการจะโอนให้ร้าน

**ผู้ดูแลระบบ**
- หน้าแรกเป็น Dashboard: ยอดซื้อและรัฐช่วยจ่ายวันนี้/เดือนนี้ ยอดรอโอน งานที่รอดำเนินการ กราฟยอดรายวัน 30 วัน และร้านยอดสูงสุด
- จัดการร้านทุกสถานะ: อนุมัติ ระงับ และเปิดใช้งานอีกครั้ง ดูรายละเอียดร้าน ยอดขาย รายการล่าสุด และบันทึกการโอนเงินให้ร้านได้
- หน้างบโครงการแสดงงบรวม งบที่ใช้ไป งบคงเหลือ และคูปองที่ออกแล้วยังไม่ใช้ (ตั้งงบรวมได้ในนโยบายโครงการ)
- จัดการแม่แบบแคมเปญที่ AI เลือกได้: เพิ่มจากกลไก 10 แบบ ตั้งช่วงค่า เปิด/ปิด และลบ (แม่แบบที่เคยใช้จะเก็บเข้าคลัง) ต้องเปิดอย่างน้อย 3 แบบ
- ภารกิจ 3 แบบ (ร้านใหม่, จำนวนครั้ง, ยอดรวม) จำกัดเฉพาะร้านได้ รางวัลเป็นเหรียญหรือคูปองเฉพาะร้านที่โครงการออกเงิน
- อนุมัติร้านใหม่
- จัดการนโยบายโครงการแบบมีเวอร์ชัน: สัดส่วนรัฐช่วยจ่าย เพดาน ค่าเหรียญ ค่าคูปอง และช่วงเวลาโครงการ
- Dashboard งบโครงการ: ยอดรัฐช่วยจ่าย คูปอง เหรียญ และยอดโอนรายร้าน พร้อมบันทึกการโอนเงินให้ร้าน
- จัดการคำร้อง: ตัดสินคำขอคืนเงินที่ร้านไม่ตอบเกิน 3 วัน และปิดเรื่องร้องเรียน
- สร้างและปิดภารกิจ
- ดู Audit log

เมื่อคืนเงิน ระบบจะทำสิ่งต่อไปนี้ใน transaction เดียว: เปลี่ยนรายการเป็น `REFUNDED`, คืนสิทธิ์รัฐช่วยจ่าย, คืนคูปองให้ใช้ได้อีก, หักเหรียญที่ได้จากรายการนั้น (ยอดเหรียญติดลบได้) และถ้ารายการนั้นทำให้ภารกิจสำเร็จ ภารกิจจะกลับไปเป็นกำลังทำ

## โครงสร้าง

```
backend/            Express API (Node.js) + test (node --test)
  src/modules/      auth, shops, payments, coupons, cases, missions, budget, policies, campaigns, analytics, ai-reports, admin
  seed/             ข้อมูล demo (สร้างจาก scripts/generate-seed.js)
frontend/           React + Vite
docker/postgres/    ไฟล์ SQL ที่รันตามลำดับตอนสร้างฐานข้อมูล
  init.sql          ตารางหลัก
  02–06_*.sql       นโยบาย/รัฐช่วยจ่าย, คูปอง, คืนเงิน/ร้องเรียน, ภารกิจ, การโอนเงินให้ร้าน
  08_*.sql          กระเป๋าเงิน, PIN และรูปหน้าร้าน (รันหลัง seed ซึ่งเป็นไฟล์ 07)
  09_*.sql          เพดานรัฐช่วยจ่ายวันละ 200 / เดือนละ 1,000 บาท
  10_*.sql          สถานะร้านปิดชั่วคราว (CLOSED)
  11_*.sql          แม่แบบแคมเปญที่ Admin จัดการได้ ภารกิจหลายแบบ และคูปองเฉพาะร้าน
  12_*.sql          เลิกใช้การอนุมัติแคมเปญเหรียญ และเพิ่มงบประมาณรวมของโครงการ (demo 500,000 บาท)
```

ไฟล์ `02`–`06` และ `08`–`12` รันซ้ำได้ ถ้าฐานข้อมูลเดิมสร้างไว้ก่อนมีไฟล์ใหม่ ให้ดูวิธีอัปเดตใน [backend/seed/README.md](backend/seed/README.md)
