# สรุปงานที่เพิ่มเติม

เอกสารนี้สรุปส่วนที่เพิ่มในงานหน้าร้าน/การชำระเงิน และงานแคมเปญ โดยพยายามคงโค้ดเดิมไว้และแก้เฉพาะจุดเชื่อมต่อที่จำเป็น

## 1. หน้าลูกค้าและการชำระเงิน

- เพิ่มหน้าเข้าสู่ระบบและสมัครสมาชิก โดยรองรับบทบาทลูกค้าและเจ้าของร้าน
- เพิ่มหน้าค้นหาร้านที่เปิดใช้งาน และหน้ารายละเอียดร้าน
- เพิ่มหน้าชำระเงินจำลอง พร้อมแสดงยอดสุทธิ ส่วนลด และ Coin ที่ได้รับ
- เพิ่มหน้าดูยอด Coin ประวัติ Coin และประวัติการชำระเงิน
- เพิ่มหน้าสร้างร้านสำหรับเจ้าของร้าน ร้านที่สร้างใหม่จะอยู่สถานะ `PENDING`
- เพิ่ม API ชำระเงิน `POST /api/v1/payments` โดยตรวจยอดเงินและสถานะร้าน บันทึก payment, redemption และ Coin ภายใน transaction เดียวกัน และรองรับ `request_key` สำหรับป้องกันคำขอซ้ำ
- เพิ่ม API สำหรับลูกค้าที่ล็อกอิน:
  - `GET /api/v1/users/me/coins`
  - `GET /api/v1/users/me/coin-transactions`
  - `GET /api/v1/users/me/payments`
- เพิ่ม `GET /api/v1/shops/public/:shopId` สำหรับดูรายละเอียดร้านที่เปิดใช้งานโดยไม่ต้องล็อกอิน

## 2. แคมเปญและการประเมินผล

- เพิ่มหน้าจัดการแคมเปญสำหรับเจ้าของร้าน:
  - ขอข้อเสนอจาก AI และเลือกข้อเสนอที่ต้องการ
  - ปรับพารามิเตอร์โปรโมชันและกำหนดวันเริ่ม/สิ้นสุด
  - สร้างแคมเปญฉบับร่าง เปิดใช้งาน และปิดแคมเปญ
  - ดูผลการประเมินหลังแคมเปญสิ้นสุด
- เพิ่ม API:
  - `POST /api/v1/ai-suggestions/:suggestionId/select`
  - `POST /api/v1/campaigns`
  - `PATCH /api/v1/campaigns/:campaignId`
  - `GET /api/v1/campaigns/:campaignId`
  - `POST /api/v1/campaigns/:campaignId/activate`
  - `POST /api/v1/campaigns/:campaignId/end`
  - `POST /api/v1/campaigns/:campaignId/evaluate`
  - `GET /api/v1/campaigns/:campaignId/result`
  - `GET /api/v1/shops/:shopId/campaigns`
- เมื่อเปิดแคมเปญ ระบบแบ่งลูกค้า `ACTIVE` เป็นกลุ่ม `TREATMENT` และ `CONTROL` แบบ deterministic ตาม hash และบันทึกการแบ่งกลุ่มพร้อมเปลี่ยนสถานะใน transaction เดียวกัน
- ป้องกันร้านมีแคมเปญ `ACTIVE` มากกว่าหนึ่งรายการ และตรวจสิทธิ์เจ้าของร้าน
- เพิ่มการคำนวณสิทธิ์ของ promotion template ที่มีใน schema และการบันทึก redemption ภายใน transaction ของ payment
- ประเมินผลตามลำดับเกณฑ์ใน `TEAM.md`: ต้องถึงเวลาสิ้นสุด, แต่ละกลุ่มต้องมีผู้เข้าเกณฑ์อย่างน้อย 20 คน, redemption อย่างน้อย 3 ครั้ง และต้องคำนวณ KPI ได้

## 3. ผู้ดูแลและ Audit log

- เพิ่มหน้า Admin สำหรับดูคำขอร้านที่รออนุมัติ และรายการ Audit log
- เพิ่ม API:
  - `GET /api/v1/admin/shops?status=PENDING`
  - `PATCH /api/v1/admin/shops/:shopId/status`
  - `GET /api/v1/admin/audit-logs`
- การอนุมัติร้านเปลี่ยน `PENDING` เป็น `ACTIVE`; การปฏิเสธเปลี่ยนเป็น `SUSPENDED` และต้องระบุเหตุผล
- บันทึกเหตุการณ์สำคัญ เช่น อนุมัติร้าน เลือกข้อเสนอ และการเปลี่ยนสถานะแคมเปญ

## 4. ไฟล์เชื่อมต่อและเอกสาร

- เพิ่ม source code ของหน้าเว็บและ route สำหรับผู้ใช้แต่ละบทบาทใน `frontend/src/`
- ผูก API modules เพิ่มเติมใน `backend/src/app.js`
- เพิ่มคำแนะนำการใช้งาน frontend ใน `frontend/README.md`

## 5. การตรวจสอบ

- Backend: `npm test` — 107 tests, ผ่าน 105, ล้มเหลว 0, ข้าม 2 รายการ เนื่องจากไม่มี PostgreSQL ขณะทดสอบ
- Frontend: `npm run lint` ผ่าน
- Frontend: `npm run build` ผ่าน

## 6. ข้อควรรู้

- การชำระเงินในระบบเป็นการจำลอง ไม่ได้เรียกเก็บเงินจริง
- การสร้างข้อเสนอแคมเปญต้องตั้งค่า AI API key ใน `backend/.env`
- หากต้องการทดสอบ integration test ที่ถูกข้าม ต้องเปิด PostgreSQL และตั้งค่าฐานข้อมูลตาม `backend/.env.example`

## 7. สิ่งที่ควรตรวจเพิ่มเติม

รายการต่อไปนี้เป็นข้อเสนอสำหรับตรวจและทดสอบต่อ ไม่ได้หมายความว่ามีการทำงานเหล่านี้เสร็จหรือยืนยันแล้ว

### ควรตรวจเป็นลำดับแรก

- [ ] เปิด PostgreSQL แล้วรัน `npm test` ใน `backend/` อีกครั้ง เพื่อให้ integration test 2 รายการที่ถูกข้ามได้ทำงานจริง
- [ ] ทดสอบ payment กับฐานข้อมูลจริง: จ่ายสำเร็จ, ร้านที่ยังไม่ ACTIVE, `request_key` ซ้ำ, ยอดเงินไม่ถูกต้อง และยืนยันว่าความล้มเหลวระหว่างบันทึก payment / coin / redemption ไม่ทิ้งข้อมูลบางส่วน
- [ ] ลอง workflow ตั้งแต่เลือก AI suggestion → สร้าง draft → เปิด → จ่ายเงินในช่วงแคมเปญ → ปิด → ประเมินผล โดยตรวจข้อมูลใน `campaign_assignments`, `promotion_redemptions`, `campaign_results` และ `audit_logs`
- [ ] ทดสอบสิทธิ์ API ด้วยบัญชีแต่ละ role: ไม่มี token, token หมดอายุ, Citizen เรียก API ของ Merchant/Admin และ Merchant พยายามเข้าถึงร้านหรือแคมเปญของเจ้าของรายอื่น

### ตรวจความถูกต้องของกฎธุรกิจ

- [ ] เทียบสูตร KPI ทั้ง 10 promotion templates และช่วง baseline กับตาราง KPI ใน `TEAM.md` โดยเฉพาะ conversion ตามช่วงเวลา/วัน, ลูกค้าใหม่, ลูกค้ากลับมา, AOV และ purchase frequency
- [ ] ตรวจว่าแคมเปญที่มีเวลาเริ่มในอนาคตจะไม่ให้สิทธิ์ก่อนเริ่ม และการปิดแคมเปญ/ประเมินผลที่เวลาขอบเขตทำงานตามที่คาด
- [ ] ตรวจการแบ่ง Treatment/Control เมื่อ `treatment_ratio` เป็น 0, 0.5 และ 1 รวมถึงกรณีเปิดแคมเปญซ้อนพร้อมกัน
- [ ] ตกลงและตรวจรูปแบบ `target_days` กับผู้สร้างข้อเสนอ AI ให้ตรงกัน (ตัวอย่างเช่น ชื่อวันภาษาอังกฤษหรือภาษาไทย)
- [ ] ตรวจนิยาม Coin ในกรณีคืนเงิน/คืนรายการ และยืนยันว่าการคืนเงินอยู่นอกขอบเขตหรือจำเป็นต้องเพิ่ม API ภายหลัง

### ตรวจหน้าจอและการเตรียมใช้งาน

- [ ] ทดลองทุกหน้าใน browser ด้วยบัญชี Citizen, Merchant และ Admin ทั้งจอมือถือและ desktop รวมถึงสถานะกำลังโหลด, ไม่มีข้อมูล และ API error
- [ ] ทดสอบการสมัคร/ล็อกอิน, token หมดอายุ และการออกจากระบบ; ตรวจว่าการ refresh หน้าไม่ทำให้หน้า role ผิดหรือแสดงข้อมูลของบัญชีก่อนหน้า
- [ ] ตรวจความพร้อมของ `VITE_API_BASE_URL`, CORS, URL ของ backend และ AI API key ใน environment ก่อน demo/deploy
- [ ] ทบทวนการแบ่งหน้าและการค้นหาในรายการร้าน/ประวัติ/รายงาน audit log หากข้อมูลมีจำนวนมาก
